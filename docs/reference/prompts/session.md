# Session Controller — fonte de verdade operacional

> **Runtime 2.5.1:** carregue primeiro `docs/context.md`. Não releia o projeto inteiro. Recupere somente o documento/detalhe adicional que a decisão exigir.


A sessão deve maximizar progresso material, não quantidade de planejamento.

Antes de começar cada bloco, escolha o melhor próximo objetivo entre trabalho ativo, cliente, oportunidade, prospecção direta e melhoria interna.

Não terminar por:

```text
pesquisa
planejamento
pequena alteração
primeiro CAPTCHA
uma única candidatura
```

Quando encontrar bloqueio humano não crítico:

```text
registrar
→ agrupar
→ continuar em outra frente
```

Quando uma tarefa começar e o próximo passo estiver claro, manter momentum.

A sessão só termina com:

```text
resultado real
AND
fila consistente
AND
próxima ação persistida
```

ou bloqueio crítico genuíno.


## Ações comprometidas

A sessão não pode terminar enquanto existir `execution_commitment` executável ou em voo. `END` não é uma saída para repetir pedido de aprovação.

Se um compromisso estiver parado sem progresso, isole o compromisso, recupere/inspecione a ferramenta e mantenha as demais frentes vivas.


## Runtime 2.5.1 — não encerrar por falta de mensagens

`NO_NEW_MESSAGE` não é `END`. A ausência de conversa dispara o `work_seeking_cycle`: verificar consequências, recorrência, mercado, prospecção, conteúdo autorizado e testes de capacidade. Somente depois, se todos os fronts estiverem esgotados, persistir o wake e entrar em `WAITING_FOR_EVENT`.
